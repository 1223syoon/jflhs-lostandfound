현재 「제주외고 분실물 센터」 프로젝트의 이미지 업로드 기능에 문제가 있다.

문제 상황:
- 분실물 등록 시 사진 파일을 선택하고 등록하면 등록 자체는 정상적으로 완료되는 것처럼 보인다.
- 하지만 사진 용량이나 해상도가 큰 이미지를 업로드하면, 이미지가 저장된 것처럼 보여도 분실물 목록이나 상세 페이지에서 이미지가 표시되지 않는 경우가 있다.
- 작은 이미지는 정상적으로 표시되는지 여부와 관계없이, 현재 이미지 업로드/저장/표시 구조 전체를 점검하고 근본적으로 수정해라.
- 단순히 이미지 영역의 CSS를 수정하는 것으로 끝내지 말고, 실제 파일 업로드 → 저장 → URL 생성 → DB 저장 → 브라우저 표시까지 전체 흐름을 확인해라.

중요:
1. 먼저 현재 프로젝트의 이미지 업로드 관련 코드를 직접 찾아서 구조를 분석해라.
   - 프론트엔드 파일 업로드 코드
   - API 업로드 처리
   - 서버 request body/file size 제한
   - 이미지 저장 방식
   - DB의 image_url 저장 방식
   - 이미지 URL을 반환하는 API
   - 목록/상세 페이지에서 이미지를 불러오는 코드
   를 모두 확인해라.

2. 현재 코드와 기존 기능을 최대한 유지하면서 수정해라.
   기존 분실물 데이터, 관리자 기능, 로그인, 상태 변경, 검색/필터 기능 등을 깨뜨리지 마라.

3. 큰 이미지도 안정적으로 처리할 수 있도록 이미지 업로드 파이프라인을 개선해라.
   - 업로드 전에 적절한 파일 형식과 크기를 검증
   - 너무 큰 원본 이미지는 서버에서 처리하기 전에 적절한 크기로 리사이즈/압축
   - 가능하면 WebP 또는 JPEG 등 웹 표시에 적합한 형식으로 변환
   - 이미지의 가로세로 비율은 유지
   - 이미지 품질을 지나치게 낮추지 말 것
   - 브라우저에서 표시 가능한 최종 이미지가 되도록 할 것

4. 파일 크기 제한 때문에 실패하는 경우를 정확하게 처리해라.
   - 서버의 multipart/body size 제한을 확인하고 필요한 범위에서 조정
   - 제한을 초과한 경우 조용히 실패하지 말고 사용자에게 명확한 오류 메시지를 표시
   - 업로드 성공 응답을 보내기 전에 실제 이미지 저장과 URL 생성이 성공했는지 확인

5. 이미지 저장은 임시 로컬 파일시스템에 의존하지 마라.
   이 프로젝트는 향후 GitHub/Vercel로 이전하여 운영할 예정이므로,
   서버리스 환경에서도 유지되는 영구적인 이미지 저장 방식을 사용해야 한다.
   현재 프로젝트에서 사용할 수 있는 persistent object/file storage가 있다면 그것을 사용하고,
   현재 저장 방식이 Vercel에서 사라질 수 있는 임시 filesystem이라면 반드시 수정해라.

6. 기존 이미지 URL 구조와 호환성을 최대한 유지해라.
   이미 DB에 등록되어 있는 분실물의 이미지가 있다면 기존 이미지가 갑자기 깨지지 않도록 고려해라.

7. 이미지 URL을 생성할 때 다음을 확인해라.
   - 브라우저에서 실제 접근 가능한 URL인지
   - 상대경로가 잘못 생성되고 있지 않은지
   - API 서버와 프론트엔드의 origin이 달라졌을 때도 정상적으로 접근 가능한지
   - URL encoding 문제가 없는지
   - 파일명이 한글/공백/특수문자를 포함해도 문제가 없는지

8. 이미지가 없는 경우에는 깨진 이미지 아이콘이 나오지 않도록 기존 empty state를 유지하거나 적절한 placeholder를 보여줘라.

9. 업로드 UI에 다음과 같은 상태를 구현해라.
   - 업로드 중: 로딩 표시
   - 성공: 미리보기 표시
   - 실패: 구체적인 오류 메시지
   - 너무 큰 파일: 사용자가 이해할 수 있는 메시지
   - 지원하지 않는 형식: 사용자가 이해할 수 있는 메시지

10. 보안도 확인해라.
   - 허용된 이미지 MIME type만 처리
   - 확장자만 믿지 말고 실제 파일 type도 검증
   - 실행 가능한 파일이나 악성 파일이 이미지로 업로드되지 않도록 방어
   - 파일명이나 URL을 통해 XSS가 발생하지 않도록 처리
   - 관리자만 이미지 업로드/수정/삭제 가능하도록 기존 서버-side authorization을 유지

11. 이미지가 실제로 표시되는지 다음 테스트를 직접 수행해라.
   A. 작은 JPG 업로드
   B. 큰 JPG 업로드
   C. 큰 PNG 업로드
   D. 스마트폰으로 촬영한 고해상도 사진 업로드
   E. 한글 파일명을 가진 이미지 업로드
   F. 이미지가 없는 분실물 등록
   G. 등록 후 새로고침
   H. 목록 페이지에서 확인
   I. 상세 페이지에서 확인
   J. 관리자에서 수정 후 다시 확인
   K. 서버를 재시작한 뒤에도 이미지가 표시되는지 확인

12. 특히 스마트폰 사진에서 발생하는 문제도 확인해라.
   EXIF orientation 때문에 이미지가 잘못 표시되거나 처리 과정에서 문제가 생기지 않도록 이미지 방향을 정상화해라.

13. 기존 DB의 image_url이 깨져 있는 경우에도 원인을 파악하고, 새로 등록하는 이미지부터는 확실하게 정상 작동하도록 수정해라.

14. 코드를 수정한 후 실제 프로젝트를 실행하여 업로드 → 저장 → DB → 표시의 전체 흐름을 테스트해라.

중요한 금지사항:
- 단순히 프론트엔드에서 이미지 크기만 줄이는 임시 해결책으로 끝내지 말 것.
- base64 이미지를 DB에 무제한으로 저장하는 방식으로 새로 구현하지 말 것.
- 서버의 임시 /tmp 또는 프로젝트 로컬 filesystem에 이미지를 저장하는 방식으로 해결하지 말 것.
- 이미지 URL을 가짜로 만들어서 해결했다고 하지 말 것.
- 기존 기능을 삭제하거나 mock 데이터로 대체하지 말 것.

마지막으로 작업이 끝나면 다음을 알려줘:
1. 현재 문제가 발생했던 정확한 원인
2. 수정한 파일
3. 이미지 저장 방식
4. 이미지 최대 업로드 크기
5. 자동 리사이즈/압축 기준
6. 기존 이미지 데이터에 미치는 영향
7. 실제로 테스트한 결과
8. Vercel 배포 후에도 이미지가 유지되는 구조인지

설명만 하지 말고 실제 코드를 검사하고 수정한 뒤 테스트까지 수행해라.
